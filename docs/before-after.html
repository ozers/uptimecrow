02 · New feature

Heartbeat monitoring — end-to-end

🗄️
Database schema + migration
apps/api/src/db/schema.ts · apps/api/drizzle/0009_heartbeats_indie_plan.sql
New

New heartbeats table with status enum, period/grace columns, and org-scoped access. Migration also adds the indie value to the plan enum.

-- Migration 0009 ALTER TYPE "plan" ADD VALUE 'indie' BEFORE 'pro'; CREATE TYPE "heartbeat_status" AS ENUM ('healthy', 'late', 'paused', 'unknown'); CREATE TABLE "heartbeats" ( "id" uuid PRIMARY KEY DEFAULT gen_random_uuid(), "org_id" uuid NOT NULL REFERENCES organizations(id) ON DELETE cascade, "slug" varchar(100) NOT NULL UNIQUE, "period" integer NOT NULL DEFAULT 86400, "grace" integer NOT NULL DEFAULT 300, "status" heartbeat_status NOT NULL DEFAULT 'unknown', "last_ping_at" timestamptz, "is_active" boolean DEFAULT true, ... );
🔌
REST API — CRUD + public ping endpoint
apps/api/src/routes/heartbeats.ts · apps/api/src/server.ts
New
Before

  • No public ping URL
  • Cron job monitoring impossible
After

  • PATCH /api/heartbeats/:id — update name/period/grace
  • DELETE /api/heartbeats/:id — org-scoped delete
  • GET /hb/:slug — public ping (no auth, rate-limited)
⚙️
Worker — late heartbeat detection every 60s
apps/api/src/jobs/heartbeat-check.job.ts · apps/api/src/worker.ts
New

BullMQ repeatable job runs every 60 seconds. Queries heartbeats where lastPingAt + period + grace < now() (and never-pinged ones where createdAt + period + grace < now()), then marks them late and logs a warning per heartbeat.

// heartbeat-check.job.ts (simplified) const overdue = await db.select(...) .where(and( eq(heartbeats.isActive, true), ne(heartbeats.status, "late"), isNotNull(heartbeats.lastPingAt), lt(sql`last_ping_at + (period + grace) * interval '1 second'`, now), )); // worker.ts additions const heartbeatCheckWorker = new Worker("heartbeat-checks", processHeartbeatCheckJob, ...); await heartbeatQueue.add("check-late-heartbeats", {}, { repeat: { every: 60_000 } });
